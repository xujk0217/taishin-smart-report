# AI 驅動企業數據轉簡報服務

## 提案與命題之連結

本提案回應企業在資料分析與管理溝通上的共同痛點：資料常分散於多份 Excel，分析需求以自然語言提出，產出卻必須是能被主管快速理解、可追溯且可再編輯的正式簡報。系統將「上傳企業資料與分析 Prompt」轉成可審閱的 AI 規劃，再依核准計畫生成簡報；因此不把 AI 當成一次性的文字產生器，而是讓它成為可驗證的分析與簡報規劃助手。

提案的核心差異在於可控性。AI 先拆解需求、頁數、指標、圖表、洞察、公式與資料來源，使用者可用自然語言或 JSON 手動修改。只有在計畫確認後，後續計算才會由程式讀取 Excel 執行；每張圖表都保留資料表、工作表、欄位、公式及計算步驟。這使成果可用於管理決策，也能回到原始資料查核。

正式參賽時，題目情境、資料集用途、授權範圍、評選要求與工作坊公告應以各組最新命題文件及企業數據工作坊公告為準。本提案不宣稱使用未授權資料，Demo 僅使用主辦方核准或去識別化的測試資料。

## 企業數據及資料應用

系統的輸入為最多 20 份 Excel 工作簿與一段自然語言 Prompt。上傳後，服務先以程式擷取各工作簿的工作表、可見欄位與有限列數樣本，建立資料輪廓；模型僅根據這些實際輪廓規劃可能的指標與圖表，不能憑空補上不存在的欄位或數字。

以管理報表情境為例，使用者可以提出「以五頁說明本期營運表現、列出關鍵 KPI、採用可追溯的圖表與公式、不得虛構資料」。系統會提出頁數與敘事順序、每個 KPI 的定義、圖表形式、資料需求及洞察問題。若指標需要計算，計畫會記錄公式、變數、單位、假設、缺值策略與零除處理，再由後續 Python 程式使用 `openpyxl` 唯讀取檔並執行計算，而不是由模型心算。

這個設計可應用於營運儀表板、銷售與成本回顧、部門績效、供應與專案進度等多種企業資料。資料價值不只在「產生一份投影片」，更在於每個結論都有可查的資料血緣：來源檔案、工作表、欄位、儲存格範圍、公式、計算步驟、結果與單位都能在最終預覽中呈現。

## AWS 雲端技術架構

前端以 CloudFront 提供 HTTPS 網頁，使用 Amazon Cognito 管理登入與授權。使用者透過 API Gateway 與 API Lambda 建立工作、取得受限時效的 S3 上傳權限及讀取自己的工作狀態；原始檔案存於非公開 S3，工作狀態與已核准的規劃版本存於 DynamoDB。

需要較長時間的 AI 規劃工作不由同步 HTTP 請求承擔。API 建立工作後交由 AWS Step Functions 協調，並啟動短生命週期的 Amazon ECS Fargate 容器。Fargate 容器讀取已授權的輸入、建立 Excel 輪廓、呼叫 Amazon Bedrock，完成後將狀態寫回 DynamoDB。此模式可避免瀏覽器等待逾時，也讓每次執行都有可追蹤的狀態：`QUEUED`、`RUNNING`、`NEEDS_REVIEW`、`APPROVED` 或安全的失敗代碼。

架構採最小權限與私有資料原則：S3 不公開、瀏覽器不持有 Bedrock 金鑰、工作只能由擁有者讀取、容器沒有對外入站服務，並透過私有 AWS 服務端點存取所需服務。ECR 保存可重現的容器映像；CloudWatch 保存不含資料內容的安全事件與階段日誌。現階段已實際啟用登入、上傳、Prompt、Fargate、Bedrock 與計畫審閱；計算執行、研究、PPT 渲染、產物下載與寄信仍明確標示為後續階段，避免將 Mock 說成已上線功能。

## 生成式 AI 技術應用

系統以 Strands Agent SDK 建立受控的規劃流程，模型推論由 Amazon Bedrock 執行。Agent 不會任意探索工具；目前僅使用受核准的結構驗證工具，並以 Pydantic schema 限制輸出格式。規劃被拆成 requirements、formula、calculation、composition 與 prompt-alignment 五個小階段，降低單次輸出過大造成截斷或錯誤的風險。

生成式 AI 的角色是理解需求與設計計畫，而非直接宣告計算答案。requirements 階段辨識受眾、目標、頁數、圖表與洞察；formula 階段提出可讀且可審閱的公式與變數；calculation 階段為每個需計算指標建立可執行的欄位綁定與程式指示；composition 階段形成逐頁簡報規劃與未來的 Python PPTX 生成方案。每一階段均有 deterministic validator：欄位必須存在、公式變數必須精確綁定、每個必要指標都要有任務、圖表需指向存在的公式與計算任務。

最後的 prompt-alignment 是獨立的模型覆核：它同時取得原始 Prompt 與完整 AIPlanningOutput，逐項標示明確需求為 covered、partial 或 missing，並要求提供計畫欄位參照。只有所有明確要求被覆蓋才可核准。最新真實 Excel 測試已完成五個階段，取得 97/100 且 `approved: true`；同一輪也確認 calculation 無須重試即通過。

## Live Demo

Demo 依下列節奏進行：

1. 使用者登入後上傳 Excel 與輸入一段管理分析 Prompt。
2. 網頁顯示工作由 `QUEUED` 進入 `RUNNING`，並在完成後呈現可編輯的 AI 規劃。
3. 展示計畫中每個 KPI、公式、Excel 欄位綁定、圖表、資料來源與預計頁數；以自然語言或 JSON 修改其中一項需求。
4. 說明資料計算將由 Python 程式讀取 Excel，不會由模型直接計算；展示每張圖表的資料血緣欄位。
5. 展示本次實測的 stage logs：requirements、formula、calculation、composition、prompt-alignment 依序完成，prompt-alignment 分數為 97 並核准。
6. 說明下一階段會依已核准計畫分析使用者 PPTX 範本、產生原生可編輯 PPTX、提供瀏覽器預覽與文字／圖表／頁數修改，最後再輸出最終檔案。

Demo 時應事先確認使用的資料已獲主辦方或資料擁有者授權，並避免展示帳號、Access Key、Session Token、預簽名 URL、個資或真實敏感商業數據。
